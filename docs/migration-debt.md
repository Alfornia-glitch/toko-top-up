# Migration debt

Temporary allowances that keep `bun run verify` green while the modular refactor
is in progress. Every entry must name an owner and the condition that removes it.
Do not add new entries silently; update this file in the same change.

| Area                           | Debt                                                                                                                                                                                                                                                                                                                                                                                      | Owner                              | Removal condition                                                                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| ESLint scope                   | `src/lib/frontend/**`, `src/lib/server/modules/**`, `src/routes/**`, `src/hooks.server.ts`, `src/hooks.client.ts`, `src/env.ts` and `src/app.d.ts` are excluded from ESLint while they still use the legacy layout.                                                                                                                                                                       | Architecture refactor              | Phase 7: routes and hooks import only module entry points; legacy folders are deleted. Replace the ignores with the final `src/**` scope.            |
| Dependency-cruiser scope       | Legacy frontend, server modules, and routes are excluded from `depcruise` so the new graph can be enforced without rewriting unreviewed code.                                                                                                                                                                                                                                             | Architecture refactor              | Phase 7: legacy code is deleted; remove the exclusions and run dependency-cruiser over all of `src`.                                                 |
| Legacy DB imports in schemas   | `src/lib/server/db/schema/{postgres,sqlite}/{catalog,commerce}.ts` import the catalog module schema for foreign keys (`reviews`, `review_images`, `cart_items`, `order_items`, `carts.coupon_id`, `coupon_redemptions`, …). The dependency-cruiser `outside-modules-only-public-entries` rule has an explicit temporary path allowance for `src/lib/server/db/schema/{postgres,sqlite}/`. | Catalog/content/customers refactor | Phase 7: move the remaining reviews and commerce schemas into their modules and delete the legacy schema tree.                                       |
| Legacy module queries          | `cart`, `checkout`, `orders`, `content` (reviews only), `customers` (user/order directory adapter in `src/lib/server/adapters`), `account`, `admin`, `reports`, `storefront` and `super` still use `#db/query.ts` and the shared legacy schema tree.                                                                                                                                      | Architecture refactor              | Phase 7: migrate each module to its own `infra/{pg,sqlite}` repositories.                                                                            |
| Catalog submodule shape        | `brands`, `categories`, `products`, and `inventory` have no own `infra/` folder. Catalog intentionally owns the aggregate schema and repository adapters so a nested module never imports a sibling's tables. Adapters live in `catalog/infra/{pg,sqlite}/repositories/`.                                                                                                                 | Catalog refactor                   | Revisit only if a submodule is promoted to a top-level module or acquires an independent data store.                                                 |
| Boundaries alias support       | `eslint-plugin-boundaries` cannot resolve Node subpath imports, so `boundaries/no-unknown-dependencies` is disabled; the local `local/module-boundaries` rule is authoritative for `#lib`, `#shared`, `#modules` and `#db` aliases.                                                                                                                                                       | Architecture refactor              | Phase 7: replace with a resolver-aware Boundaries setup and re-enable the rule.                                                                      |
| Existing DB rename             | `migrations/pg` and `migrations/sqlite` are fresh baselines. Existing local databases must run `bun scripts/rename-catalog-tables.ts` once to rename `brands`/`products`/… to `catalog_*`. The app has not been deployed, so no production data migration is required yet.                                                                                                                | Platform refactor                  | Keep the script until the deployed baseline includes `catalog_*`; then document it as historical.                                                    |
| Postgres contract tests        | `test/contracts/catalog/*.pg.test.ts` skip unless `TEST_DATABASE_URL` is set. CI provides it; local `bun run test` only exercises SQLite contracts.                                                                                                                                                                                                                                       | Architecture refactor              | Keep as-is; `bun run test:pg` remains the explicit Postgres gate.                                                                                    |
| E2E                            | Playwright is configured with a single smoke test but is not part of `verify`.                                                                                                                                                                                                                                                                                                            | Architecture refactor              | Phase 8: add the route smoke matrix and run it in CI.                                                                                                |
| Legacy reads of catalog tables | `storefront`, `cart`, `checkout`, `account/wishlist`, `content/reviews`, `reports` and `super` query `catalog_*` tables directly; `check:data` does not scan `src/lib/server/modules`.                                                                                                                                                                                                    | Architecture refactor              | Phase 7: read catalog data through the catalog public API, then extend `check:data` to all of `src`.                                                 |
| Coupon redemption in checkout  | Legacy `cart` and `checkout` read and update `marketing_coupons` directly; checkout increments `used_count` and writes `coupon_redemptions` inside the order transaction, so it is not behind the marketing module.                                                                                                                                                                       | Architecture refactor              | Phase 7: when `checkout` and `orders` migrate, move redemption behind the marketing module (or a shared transaction port) and drop the direct reads. |
